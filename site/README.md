# Витрина Уклада

Публичная страница продукта: дашборд статусов работ, роадмап и журнал
обновлений. Отдельный от приложения проект со своей сборкой — у витрины другой
читатель (тот, кто ещё не пользуется Укладом) и другой ритм правок.

## Запуск

```bash
cd site
npm install
npm run dev      # http://localhost:5175 (порт закреплён, редактор рядом на 5174)
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | дев-сервер на 5175 |
| `npm run build` | типы + продакшен-сборка в `site/dist` |
| `npm run preview` | посмотреть собранное |
| `npm run lint` | `tsc -b --noEmit` |
| `npm test` | Vitest: расчёты роадмапа |

## Что на странице

**Статус работ** (`#status`) — сколько задач в каждой стадии, общая доля
готового и крупные этапы с двухсегментной полосой: сделанное и то, что пишется
сейчас. Плитка стадии фильтрует борд ниже.

**Роадмап** (`#roadmap`) — тот же список в двух видах: колонками по стадиям
(«чем заняты») и по кварталам («когда будет»). Поиск, фильтр по направлению,
голос за пункт.

**Обновления** (`#releases`) — журнал вышедших версий.

## Как править роадмап

Всё содержимое — в `src/data/roadmap.ts`: пункты (`ITEMS`), крупные этапы
(`MILESTONES`), журнал (`RELEASES`). Бэкенда и админки нет намеренно: роадмап
меняется раз в неделю руками, правка = коммит, история правок = история git.

Правила, которые проверяют тесты (`npm test`):

- идентификаторы пунктов уникальны — иначе голос уйдёт не туда;
- каждый пункт привязан к существующей вехе;
- у `status: "done"` есть `shippedAt` и `version`, у остальных `shippedAt` нет:
  «планировали на квартал» и «вышло тогда-то» — разные даты и путать их нельзя;
- версия готового пункта есть в `RELEASES`;
- квартал записан как `2026-Q4`.

Внешние адреса (демо, репозиторий, issues) и версия прототипа — в
`src/data/site.ts`.

## Голоса

Голос посетителя живёт в его браузере (`localStorage`, `lib/votes.ts`) и
прибавляется к числу из `roadmap.ts`. Механика честная в одну сторону: человек
видит, за что голосовал, но общий счётчик от его клика не растёт для других.
Когда появится сервер, меняется `votes.ts`, а не карточки.

## Тема

Палитра берётся из редактора: `src/tokens.css` генерируется из
`../src/index.css` командой `npm run tokens` **в корне репозитория**. Руками
этот файл не правят — правят источник. Своё у витрины только то, чего в
редакторе нет: цвета стадий роадмапа (`--st-*` в `src/index.css`) и оформление
страницы.
