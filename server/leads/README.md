# Приёмник заявок

Функция Яндекс Облака, которая принимает заявки с витрины и кладёт их письмом
в почтовый ящик. Три файла, ни одной зависимости кроме `nodemailer`:

| Файл       | Что делает                                                         |
| ---------- | ------------------------------------------------------------------ |
| `index.js` | точка входа: CORS, метод, разбор тела, ответ браузеру              |
| `lead.js`  | проверка заявки и сборка письма — вся логика, которую стоит читать |
| `mail.js`  | отправка по SMTP                                                   |

## Почему это отдельная функция, а не вебхук CRM

Vite подставляет переменные с префиксом `VITE_` в собранный код **значением, в
открытом виде**. Адрес приёмника лежит в `VITE_LEADS_ENDPOINT`, то есть виден
каждому, кто откроет исходник страницы. Вебхук Битрикс24 или amoCRM носит токен
прямо в адресе — опубликовать такой адрес значит отдать постороннему право
писать в CRM. У функции в адресе нет ничего, кроме её идентификатора; пароль
ящика лежит в переменных окружения на стороне облака и в браузер не попадает.

Второе: как только заявки начинает принимать сервер, начинается обработка
персональных данных, а ч. 5 ст. 18 152-ФЗ требует, чтобы база с данными
россиян находилась в России. Яндекс Облако этому отвечает.

## Что функция делает с заявкой

1. Отвечает на предварительный запрос `OPTIONS`. Он приходит всегда: витрина
   шлёт `Content-Type: application/json`, а такой запрос браузер простым не
   считает. Без ответа на `OPTIONS` форма не отправится ни разу.
2. Сверяет `Origin` со списком разрешённых. Это не рубеж обороны — заголовок
   ставит браузер, — а отсечение случайного: чужой страницы, встроившей нашу
   форму себе.
3. Ограничивает тело 32 КБ и разбирает JSON.
4. Проверяет заявку целиком: вид, язык, тему, письмо, длины полей и —
   обязательно — согласие на обработку персональных данных (`consent.data`).
   Без него обработку начинать нельзя вовсе, ч. 1 ст. 9 152-ФЗ. Витрина без
   галочки отправить не даёт, но проверять это на стороне браузера
   бессмысленно.
5. Отправляет письмо на `MAIL_TO`, подставляя в `Reply-To` первый адрес,
   найденный среди полей заявки, — иначе ответ ушёл бы самому себе.

Наружу отдаётся только код состояния: `200` — принято, `400` — заявка не
прошла проверку, `403` — чужой источник, `413` — тело великовато, `502` —
письмо не ушло. Причина отказа пишется в журнал функции, а не в ответ:
подробный разбор того, какая проверка не прошла, полезен только тому, кто
подбирает обход.

Витрина на любой неуспех показывает «не вышло» и предлагает отправить то же
самое обычным письмом (`src/site/lib/leads.ts`), так что заявка не теряется.

## Развёртывание

1. **Ящик.** Завести `hello@u-klad.ru` (Яндекс 360 для домена) и создать для
   него **пароль приложения** — обычный пароль от учётной записи в SMTP не
   подойдёт, если включена двухфакторная аутентификация.
2. **Функция.** В консоли Яндекс Облака: создать функцию, версию с рантаймом
   `nodejs22`, точка входа `index.handler`, загрузить содержимое этой папки
   (`index.js`, `lead.js`, `mail.js`, `package.json` — облако само поставит
   `nodemailer` по `package.json`). Таймаут 10 секунд, память 128 МБ.
3. **Публичный вызов.** Включить «Публичная функция», иначе браузер получит
   `403` ещё до кода.
4. **Переменные окружения** — на вкладке версии:

   | Переменная       | Обязательна | Значение                                               |
   | ---------------- | ----------- | ------------------------------------------------------ |
   | `SMTP_USER`      | да          | `hello@u-klad.ru`                                      |
   | `SMTP_PASSWORD`  | да          | пароль приложения                                      |
   | `MAIL_TO`        | да          | куда складывать заявки                                 |
   | `ALLOWED_ORIGIN` | нет         | по умолчанию `https://u-klad.ru`; список через запятую |
   | `SMTP_HOST`      | нет         | по умолчанию `smtp.yandex.ru`                          |
   | `SMTP_PORT`      | нет         | по умолчанию `465` (SSL)                               |
   | `MAIL_FROM`      | нет         | по умолчанию `SMTP_USER`                               |

   Недостача обязательной переменной валит функцию сразу, а не на первом
   человеке, который что-то написал: молчаливое «письмо не ушло» — худший
   исход для формы.

5. **Адрес функции** вписать в `.env.local` витрины:

   ```
   VITE_LEADS_ENDPOINT=https://functions.yandexcloud.net/<идентификатор>
   ```

   и пересобрать сайт. Пока переменная пуста, форма честно называет кнопку
   «Написать письмо» и открывает почтовый клиент — это рабочее состояние, а не
   недоделка.

## Проверить, что работает

```bash
curl -i -X OPTIONS https://functions.yandexcloud.net/<идентификатор> \
  -H "Origin: https://u-klad.ru" \
  -H "Access-Control-Request-Method: POST"
```

Ожидается `204` и заголовок `Access-Control-Allow-Origin: https://u-klad.ru`.
Затем — настоящая заявка из формы на сайте: письмо должно прийти в течение
минуты, а в журнале функции не должно быть ничего.

## Если пойдёт спам

Отдельной защиты здесь нет намеренно: на сайте без посетителей она защищала бы
от никого. Когда спам появится, порядок такой — сначала [Яндекс
SmartCaptcha](https://yandex.cloud/ru/services/smartcaptcha) (её проверка
делается одним запросом прямо здесь, до отправки письма), и только потом всё
остальное. Ограничение частоты по адресу без внешнего хранилища не сделать:
контейнеров у функции несколько и они не общие.
