# Карточка склада — контракт данных формы

6 октября 2026. Что склад вводит в форме лендинга, что из этого видно селлеру и как это приходит на
backend. Нужен до дизайна: первый экран показывает карточку, а форма и приёмник должны принимать
те же поля. Метки: **[Факт]** из кода · **[Решить]**.

## 1. Две ступени, а не одна форма

Форма на лендинге короткая — только чтобы ответить. Остальное склад заполняет **после «да»**,
в черновике карточки (позже, в кабинете или по ссылке из письма).

**Ступень 1 — форма на лендинге (обязательно всё, кроме отмеченного):**

| Поле                                           | Тип                                 | Зачем                         |
| ---------------------------------------------- | ----------------------------------- | ----------------------------- |
| Название склада                                | строка до 120                       | заголовок карточки            |
| Город                                          | строка / выбор из `cities.ts`       | по городу идёт фильтр витрины |
| Контакт                                        | строка: телефон, почта или Telegram | куда писать для проверки      |
| Имя контактного лица _(необязательно)_         | строка                              | как обращаться                |
| Согласие на обработку данных                   | галочка, не проставлена заранее     | 152-ФЗ, ст. 9                 |
| Согласие на рекламные письма _(необязательно)_ | галочка, отдельная                  | ст. 18 ФЗ «О рекламе»         |

Больше полей на ступени 1 не добавлять: каждое лишнее поле снижает долю ответивших.

**Ступень 2 — после «да» (склад или мы по его словам):**

| Поле                                        | Тип `Warehouse` (`src/site/data/warehouses.ts`) | Видно селлеру                                              |
| ------------------------------------------- | ----------------------------------------------- | ---------------------------------------------------------- |
| Адрес, координаты                           | `address`, `lat`, `lng`                         | город и район; точный адрес — после заявки **[Решить]**    |
| Год начала работы                           | `since`                                         | да                                                         |
| Площадь, м²                                 | `areaM2`                                        | да                                                         |
| Всего мест / свободно                       | `cellsTotal`, `cellsFree`                       | да — главный сигнал витрины                                |
| Схемы работы                                | `schemes` (FBO/FBS/DBS)                         | да                                                         |
| Маркетплейсы                                | `marketplaces`                                  | да                                                         |
| Услуги                                      | `services`                                      | да                                                         |
| Цены: хранение, приёмка, сборка, маркировка | `price.storage/receiving/picking/marking`       | да; склад сам решает, показывать ли                        |
| Минимальный объём                           | `minPlaces`                                     | да                                                         |
| Дата подтверждения цен и мест               | `confirmedAt`                                   | да, без неё карточка выглядит брошенной                    |
| Описание                                    | `pitch`                                         | да                                                         |
| Фото _(необязательно)_                      | `photo`                                         | да                                                         |
| Работает ли на Укладе                       | `uklad`                                         | ставит система, не склад                                   |
| Проверен                                    | `verified`                                      | ставим мы после сверки госрегистрации и права на помещение |

**Остаётся у склада и наружу не идёт:** остатки и заказы клиентов, данные покупателей посылок,
внутренние тарифы для конкретных клиентов.

## 2. Как это пришло бы на backend

**[Факт]** Приёмник заявок уже есть — функция Яндекс Облака в `server/leads/` (проверяет заявку и
отправляет письмом; `docs/LAUNCH.md`, п. 6). Формат тела: `kind`, `lang`, `subject`, `page`,
`message`, `fields` (до 30 пар «подпись — значение»), `consent: { data, ads }`.

Что надо изменить, чтобы принять карточку:

1. **Новый вид заявки `card`.** Сейчас допустимы `contact | request | complaint | vote | idea`
   (`server/leads/lead.js`, `KINDS`; тип `LeadKind` в `src/site/lib/leads.ts`). Добавить `card` в оба
   места, иначе приёмник ответит «неизвестный вид заявки».
2. **Поля ступени 1 — это `fields`:** «Название склада», «Город», «Контакт», «Имя».
3. **Тема письма:** `Карточка склада: {название}, {город}` — по теме потом ищется в почте.
4. **Куда идёт письмо:** на ящик из `MAIL_TO`; пока бесплатно на личный ящик (`docs/LAUNCH.md`, п. 4).

**Если владелец делает свой backend с базой вместо письма** — те же поля, плюс таблица
`warehouse_cards`: `id`, `created_at`, поля ступени 1, `consent_data_at`, `consent_ads`,
`consent_text_version`, `status` (`new → checked → published → hidden`), `source` (откуда пришёл:
ссылка из сообщения, UTM). Факт согласия хранить с датой, текстом и версией (требование
`docs/LAUNCH.md`, п. 6).

## 3. Статусы карточки

`new` — пришла с формы · `checked` — мы связались, данные проверены · `published` — склад
сказал «да», карточка на витрине · `hidden` — склад попросил убрать или перестал отвечать.
Публикуется только `published`; ничего не показывается снаружи до «да» (см. `LANDING-WAREHOUSES.md`, п. 5).

## 4. Решить

- **[Решить]** Показывать ли точный адрес склада до заявки селлера (риск: склад получает звонки
  в обход витрины; польза: доверие).
- **[Решить]** Показывать ли цены обязательно или по желанию склада. У full-full.ru цены нет — это
  их слабость, а у нас цена как раз отличие; но склад может не захотеть. Предложение: цена по
  желанию, но карточка без цены сортируется ниже.
- **[Решить]** Кто вводит данные ступени 2 — склад в кабинете (нужна авторизация, которой нет) или
  мы по его словам на первых 10 складах. Рекомендую второе: быстрее и даёт разговор.
