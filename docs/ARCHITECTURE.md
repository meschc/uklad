# Архитектура

Документ на одну страницу: с чего начинать чтение кода и почему он устроен
именно так. Подробные карты модулей — в `docs/CODEMAPS/`, соглашения по стилю
и командам — в `CLAUDE.md`.

## Что это за проект

Уклад — две вещи в одном репозитории:

- **витрина** (`/`) — маркетплейс фулфилмент-складов: лендинг, каталог,
  страница склада, тарифы, контакты, правовые документы;
- **кабинет** (`/app/`) — WMS: 2D-план склада, приёмка, задания, сборка,
  наклейки, документы, каталог товаров, персонал, аналитика.

Backend'а пока нет. Данные живут в браузере (`localStorage` через `persist`
Zustand), а весь код написан так, чтобы появление сервера было заменой одного
слоя, а не переписыванием экранов. Ниже — как именно.

## Две точки входа

Vite собирает **MPA**, а не одностраничник (`vite.config.ts`, `rollupOptions.
input`):

```
index.html      → src/site/main.tsx  → витрина
app/index.html  → src/main.tsx       → кабинет
```

Причина в весе и аудитории. Селлер приходит на `/` за складом; кладовщик
открывает `/app/` и тянет туда редактор плана, three.js и всю доменную логику.
Общий бандл означал бы, что лендинг грузит редактор ради первого экрана.

`base` не задан: адреса абсолютные от корня домена.

### Стили: что общее, а что нет

`src/index.css` делят оба входа — там токены темы и база Tailwind. Всё
остальное разъехалось по своим файлам: витрина — `src/site/site.css` (тёмная
палитра, своя шкала радиусов, появление по скроллу), печать кабинета —
`src/print.css` (импортируется только из `src/main.tsx`).

Разделение не косметическое. Печать кабинета устроена как «спрятать всё,
вернуть видимость поддереву `.print-root`», и пока это правило лежало в общем
файле, оно ехало на витрину, где никакого `.print-root` нет: «Скачать PDF» в
правовом документе отдавал пустые листы. На экране такое не видно вообще —
`@media print` не показывает ни браузер, ни скриншотный тест. Правило: если
стиль верен только для одной половины, он живёт в файле этой половины.

## Маршрутизация — разная в двух половинах

**Витрина** ходит по путям: `/market/`, `/warehouse/w-12/`, `/en/pricing/`.
Список адресов один и лежит в `src/site/lib/routes.ts` (`SITE_ROUTES`) — по
нему же собирается `sitemap.xml` и предрендер. Переходы внутри витрины
перехватывает `useLinkNavigation` и делает их без перезагрузки, но каждая
ссылка остаётся настоящей `<a href>`: то, что открывается по адресу, должно
открываться и по правому клику, и у робота.

**Кабинет** переключает экраны полем стора `appView` (`src/App.tsx`), адрес не
меняется. Это осознанно: кабинет — рабочее место на смену, ссылками из него не
делятся. Единственное исключение — `?heatmap=1`: отдельное окно тепловой карты,
читающее тот же `localStorage`.

## Слои

```
данные        src/lib/data/**            репозитории, конверт Result
хранилище     src/lib/store/**           Zustand + persist (локальный кэш)
логика        src/lib/*.ts               чистые функции: placement, fulfillment,
                                         documents, barcode, lookup, importProducts
интерфейс     src/components/**          React, знает только о сторе и данных
витрина       src/site/**                свои данные, своя копирайт-система, SSR
```

Правило одно и держит всё остальное: **зависимости идут сверху вниз**. Чистая
логика не знает о сторе, стор не знает о React, компонент не лезет в
`localStorage` мимо слоя данных.

### Слой доступа к данным — главный шов

`src/lib/data/` — по одному тонкому репозиторию на домен: `requests`, `chat`,
`fulfillment`, `catalog`, `placement`, `staff`. Имя репозитория повторяет имя
среза стора — это соглашение, а не совпадение.

Четыре решения, принятые заранее, ради того чтобы код вызывающих не менялся
при появлении сети:

1. **Сигнатуры асинхронные** (`Promise<T>`), хотя внутри синхронный Zustand.
2. **Ответ всегда в конверте** — `Result<T>` из `result.ts`: либо
   `{ ok: true, data }`, либо `{ ok: false, error: MsgKey }`. У каждого вызова
   уже есть ветка «не вышло».
3. **Исключение становится ответом ровно в одном месте** — в `attempt()`.
4. **Порт наружу узкий**: `StorePort { get, set }`. Подменив его, репозиторий
   тестируется без стора и переводится на сеть без правки экранов.

Важное различие, которое легко потерять: **отказ предметной области — это
успех, а не сбой**. «Категория с таким именем уже есть» возвращается как
`ok: true, data: false`, а не как ошибка. Ошибка — только сорванный транспорт,
и только по ней в интерфейсе появляется кнопка «Повторить».

Репозиторий — путь **команд и разовых чтений** (импорт, экспорт, диалоги,
проверки). Реактивный рендер по-прежнему подписан на стор: стор здесь и есть
локальный кэш, ровно как он останется кэшем при настоящем сервере.

Состояние одной команды в интерфейсе держит хук `useCommand`: `{ run, pending,
error, reset }`.

### Витрина: отдельный репозиторий и отдельная причина

`src/site/data/warehousesRepository.ts` — тот же приём для каталога складов:
`list`, `get`, `search`, `stats`, `featured`. Компоненты витрины не знают
массива `WAREHOUSES`.

Но он **синхронный**, в отличие от `@/lib/data`, и это намеренно. Витрина
предрендеривается: её страницы собираются на сборке, и асинхронное чтение
отдало бы поисковику пустые страницы, дорисовывающиеся только в браузере.
Настоящий реестр складов придёт тоже **на сборке** — скрипт положит выгрузку
рядом, и этот один файл станет читать её вместо генератора.

## Что остаётся локальным после появления сервера

Решено заранее, чтобы `localStorage` не стал тихо второй правдой.

**Локально остаются только предпочтения интерфейса** — то, что относится к
устройству, а не к складу:

| Что                               | Где                                  |
| --------------------------------- | ------------------------------------ |
| язык витрины                      | `site/lib/lang.ts`                   |
| выбор в баннере cookie            | `site/lib/cookieConsent.ts`          |
| свёрнутые секции панели редактора | `components/editor/PanelSection.tsx` |
| тема кабинета                     | поле `profile.theme` в сторе         |

Тема витрины не хранится вовсе: она берётся из настройки устройства
(`site/lib/theme.ts`), переключателя на сайте нет.

Всё это пишется через `src/lib/safeStorage.ts` и переживает недоступное
хранилище: чтение возвращает `null`, запись молчит. В приватном окне Safari и
при сборке в Node прямой вызов `localStorage` бросает исключение — обёртка
существует именно поэтому.

**Всё доменное приходит с сервера.** Список полей в `partialize`
(`store/index.ts`) — склад, товары, размещения, заявки, поставки, короба,
паллеты, переписка, персонал, шаблоны — становится кэшем ответа, а не
источником правды. Практические следствия, которые надо будет соблюсти:

- версия персиста (`version: 8`) перестаёт описывать формат данных и начинает
  описывать формат кэша; миграции остаются, но их цена падает;
- `sanitizeDomains` в `merge` уже написан на случай мусора в хранилище — он же
  примет на себя первый неожиданный ответ сервера;
- сброс к демо-данным (`Профиль → сбросить`) чистит ключ персиста и
  перезагружает страницу; после появления сервера он превратится в очистку
  кэша, а не данных.

## Тексты и языки — две системы, и это не дублирование

- **Кабинет**: `src/lib/i18n/` — словарь по доменным файлам, ключ выведен из
  русской половины (`MsgKey = keyof typeof ru`), а `en` объявлен как
  `Record<MsgKey, string>`. Пропущенный перевод не собирается.
- **Витрина**: `src/site/lib/copy.ts` — пара `c(ru, en)` прямо рядом с
  компонентом.

Разница по сути задачи. В кабинете строка живёт в коде и переводится один раз;
на витрине текст — часть верстки, его правят вместе с блоком, и вынос в общий
словарь превратил бы правку абзаца в путешествие по трём файлам.

Общее правило типографики (`translate` / `noOrphans`): предлоги и короткие
слова приклеиваются к следующему неразрывным пробелом. Это касается и
атрибутов DOM — строгий селектор по `placeholder` с обычным пробелом ничего не
найдёт.

## Сборка и предрендер

```
npm run build  =  tsc -b && vite build && npm run build:ssr && node scripts/prerender.mjs
```

`prerender.mjs` берёт `SITE_ROUTES`, рендерит каждый адрес серверной сборкой и
кладёт готовый `index.html` рядом: `/market/` → `dist/market/index.html`. Там же
собирается `sitemap.xml`. Контрольная цифра на сегодня — **154 страницы и карта
сайта на 77 адресов**; если после правки число изменилось не потому, что вы
добавляли страницы, — что-то сломалось.

Готовая разметка не гидрируется, а перерисовывается заново: у витрины есть
состояния, которых на сборке не существует (тема устройства, язык из памяти
браузера, согласие на cookie), и «подхват» серверной разметки упирался бы в
расхождения на каждой второй странице. Разметка нужна тому, кто скриптов не
выполняет; остальным она безвредна.

## Тесты

Vitest, окружение по умолчанию — **node**: проверяются расчёты, которые
ошибаются молча. Компонентный тест включает jsdom комментарием
`// @vitest-environment jsdom` в первой строке. Файлы — рядом с кодом, в
`__tests__/`. E2E — Playwright (`npm run test:e2e`, свой порт 4174).

Стор целиком в тестах не поднимается: у среза свой стенд
(`lib/store/__tests__/harness.ts`), у репозитория — подменённый `StorePort`.
