# Решения (ADR)

Короткие записи о решениях, которые дорого пересматривать: почему нет бэкенда,
почему две точки входа, почему свой словарь, почему свой чат, где витрина
сходится с кабинетом. Ответы на эти вопросы жили в комментариях по коду — то
есть находились только тем, кто уже открыл нужный файл. Здесь они собраны в
одном месте.

Запись — не документация и не инструкция. Она отвечает на один вопрос: что
было известно в тот момент и почему выбрали это. Устаревшая запись не
переписывается — заводится новая, со ссылкой на прежнюю, а у прежней меняется
статус.

| №                                                | Решение                                       | Статус  |
| ------------------------------------------------ | --------------------------------------------- | ------- |

| [0002](0002-mpa-two-entry-points.md)             | MPA: витрина и кабинет — две сборки           | Принято |
| [0003](0003-own-i18n.md)                         | Свой словарь вместо i18n-библиотеки           | Принято |

## Как добавить запись

Файл `NNNN-краткое-имя-латиницей.md`, номер по порядку, содержание — русское.
Разделы: **Статус**, **Контекст**, **Решение**, **Последствия**, **Когда
пересматривать**. Полстраницы достаточно; если получается больше — скорее всего,
это уже архитектурный обзор, и ему место в
[`docs/ARCHITECTURE.md`](../ARCHITECTURE.md).

Статусы: `Принято`, `Заменено #NNNN`, `Отменено`.
