# 0007. Одна дизайн-система на витрину и кабинет

**Статус:** принято · 2026-10

## Контекст

Витрина и кабинет — две сборки ([0002](0002-mpa-two-entry-points.md)), но для
селлера это один продукт: на витрине он выбирает склад, в кабинете видит свой
товар на его полках. Запись 0002 считала общими токены, `cn` и примитивы `ui/`,
а на деле половины успели разойтись:

- `src/site/site.css` переопределяет палитру целиком: свои `--background`,
  `--primary` и остальные роли для обеих тем. Синий витрины — тон 226°, синий
  кабинета — 221° в светлой теме и 214° в тёмной. «Один продукт» держится на
  двух палитрах.
- Витрина не берёт из `src/components/ui/` ни одного примитива. Надзаголовок
  собран дважды (`src/site/lib/eyebrow.ts` рядом с `ui/eyebrow.ts`), а в ветке
  `feat/marketplace-site` появился `siteButton` со своими высотами — мимо
  правила трёх ступеней 32 / 36 / 40.
- Описание дизайн-системы живёт в двух местах: `docs/design/` (для Figma) и
  артефакт https://claude.ai/artifact/Tadqydujk1gJrKcysRePzm — для тех, кто код не открывает. Артефакт снят с `main`
  (шрифт Golos, прежняя марка), а ветка витрины уже перешла на Geist и новую
  марку. О расхождении можно было узнать только случайно.

## Решение

Дизайн-система одна, и источник у неё один — код.

1. **Токены** — только в `src/index.css`: цвета по ролям для обеих тем, шрифт,
   шкалы. `npm run tokens` пересобирает из них `docs/design/design-tokens.json`.
   Своих значений для тех же ролей витрина не заводит.
2. **Примитивы** — `src/components/ui/` для обеих половин. Витрине можно
   добавлять поверх характер — шкалу скруглений (`--r`), ритм длинной страницы,
   появление блоков по скроллу, — но не цвета и не высоты контролов.
3. **Артефакт правится вместе с кодом**, в той же задаче: поменялся токен,
   примитив, шрифт или марка — обновляются `docs/design/` и артефакт. Правка,
   ушедшая в код без артефакта, — ошибка, а не «потом».

## Последствия

- Сведено 7 октября 2026 (задача `design-shared` на карте продукта):
  - палитры витрины больше нет — в `site.css` не осталось ни одного цвета,
    только скругление `--r` и правила печати (серый лист, акцент — чернилами);
    `--brand` и `--brand-strong` сняты, текстовый акцент — общий `--primary`,
    он держит AA в обеих темах;
  - `siteButton` и `ctaPill` удалены, все кнопки витрины — `ui/button` с
    формой `shape="pill"`; главный призыв со стрелкой — `CtaLink` поверх той
    же кнопки, 40 px вместо прежних 48;
  - `src/site/lib/eyebrow.ts` удалён, рубрика над заголовком секции —
    `eyebrow({ tone: "primary" })` из `ui/eyebrow`;
  - `npm run tokens` выгружает два набора цветов (`color.light|dark`) вместо
    четырёх.
- Знак (синяя плитка) — не токен темы, а постоянный цвет `#426EFF`: фавикон и
  превью для соцсетей живут вне сборки и токенов не видят. Копии — `Logo.tsx`
  (`MARK_BLUE`), `public/favicon.svg`, `public/og.svg`.
- Не сведено: предупреждающего тона в палитре нет — витрина и кабинет пока
  берут `amber-*` из Tailwind, а кабинет местами ещё `emerald-*` вместо
  `--success`. Это отдельная задача: сначала токен `--warning`, потом замены.
- Цена: витрина больше не может «подкрутить синий» у себя — правка цвета видна и
  в кабинете. Это и есть цель: селлер переходит из одного в другое и не должен
  замечать шва.

## Когда пересматривать

Если витрина станет отдельным брендом — другой продукт для другой аудитории, —
раздельные палитры будут честнее одной.
