# 0008. Кабинет — на поддомене app.u-klad.ru

**Статус:** принято, переезд не завершён · 2026-10

## Контекст

Сейчас кабинет — второй вход той же сборки
([0002](0002-mpa-two-entry-points.md)) и открывается по `u-klad.ru/app/`: обе
половины уезжают на GitHub Pages одним деплоем. Владелец решил вынести рабочее
место на свой адрес — `app.u-klad.ru`:

- сайт и рабочее место — разные вещи, и это должно быть видно уже по адресу;
  ссылку на кабинет можно давать отдельно от сайта;
- правила у них разные: витрину индексируют, кабинет нет; со временем у
  кабинета появится вход, и его cookie не должны жить вперемешку с витринными;
- когда появится бэкенд, кабинет переедет к нему, а витрина может остаться
  статикой — раздельные адреса этого не помешают.

Препятствие одно: GitHub Pages даёт репозиторию один свой домен, и `u-klad.ru`
уже занят витриной.

## Решение

1. **Сборка.** `npm run build:app` собирает один кабинет в `dist-app/` с корнем
   `/`: `app/index.html` становится `index.html`, рядом — иконки, шрифты, знаки
   партнёров и `robots.txt` с полным запретом. Это обычная статика, её можно
   положить на любой хостинг. CI собирает её на каждое изменение, чтобы она не
   сломалась молча, пока поддомен не подключён.
2. **Старый адрес живёт.** `npm run build` не меняется: кабинет остаётся и по
   `/app/`, пока поддомен не заработает, — уже разосланные ссылки не ломаются.
3. **Хостинг поддомена** выбирает владелец; варианты и шаги — в
   [`docs/LAUNCH.md`](../LAUNCH.md), «Кабинет на app.u-klad.ru». В любом случае
   нужна одна DNS-запись `app` в REG.RU.
4. **Когда поддомен заработает**, ссылка «Демо WMS» в подвале витрины
   (`SiteFooter`, сейчас `withBase("app/")`) ведёт на `https://app.u-klad.ru/`,
   а `/app/` на витрине заменяется переадресацией туда же.

## Последствия

- `localStorage` привязан к адресу: на `app.u-klad.ru` кабинет откроется с
  чистыми демо-данными, накликанное на `u-klad.ru/app/` туда не переедет. Тема —
  тоже: скрипт в `app/index.html` читает её из того же хранилища. Для демо это
  приемлемо, а настоящие данные всё равно уедут в бэкенд
  ([0001](0001-local-storage-instead-of-backend.md)).
- Переход «витрина → кабинет» становится переходом между адресами, но он и так
  был полной загрузкой страницы — новой цены нет.
- Ссылок из кабинета на витрину нет, и так должно остаться: на поддомене путь
  `/legal/…` вёл бы в сам кабинет. Понадобится такая ссылка — только полным
  адресом.
- Деплоев станет два. Токены и `ui/` собираются в оба, поэтому выкладывать их
  нужно из одного коммита, иначе витрина и кабинет разъедутся по виду
  ([0007](0007-odna-dizajn-sistema.md)).

## Когда пересматривать

Когда у кабинета появится бэкенд со входом: тогда хостинг кабинета выбирается
вместе с хостингом API, а не отдельно.
