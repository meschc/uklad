# 0009. Postgres с изоляцией компаний в самой базе

Дата: 24.10.2026. Статус: Принято (архитектура данных согласована владельцем 24.10).

## Контекст

Кабинет переезжает из localStorage на свой сервер в РФ. Компаний много, и
склад работает с несколькими селлерами, селлер — с несколькими складами.
Утечка одного чужого остатка — это конец доверия к продукту. Владелец
работает один, поэтому защита не должна держаться на внимательности при
каждой правке экрана.

## Решение

- Одна база Postgres, все компании в одних таблицах, у каждой строки
  `org_id`.
- Row Level Security с `FORCE` на каждой таблице. Компания ставится в
  транзакции (`set_config('app.org_id', …, true)`); без неё не видно ничего.
- Приложение ходит ролью без `BYPASSRLS`, не владельцем таблиц и без права
  `DELETE`. Миграции — отдельной ролью.
- Составные внешние ключи `(org_id, id)`: строка одной компании не ссылается
  на строку другой.
- Видимость товара селлеру решает база по активному договору, а не фильтр
  экрана.
- Тесты изоляции — отдельное обязательное задание CI.

## Почему не иначе

- **База на компанию** надёжнее разделяет, но миграции, копии и связи
  склад ↔ селлер становятся кошмаром для одного человека.
- **Фильтр `WHERE org_id = …` в коде** без RLS держится на том, что его ни
  разу не забудут. Забудут.
- **Supabase** даёт то же RLS, но это облако; облака владелец не хочет.

## Последствия

- Изоляция держится на одном: `app.org_id` ставит только серверный код из
  сессии. Поэтому только параметризованные запросы и никаких значений от
  пользователя в `set_config`/`SET`: SQL-инъекция обошла бы RLS сменой
  компании.
- `set_config` и `SET` для `app.*` (`org_id`, `member_id`, `warehouse_id`,
  `account_id`) вызывают только функции схемы `auth`, код сервера — никогда.
  CI проверяет это поиском по `server/api/src`.
- Каждая новая таблица обязана иметь `org_id`, RLS, FORCE — иначе падает CI.
- Запросы чуть медленнее из-за политик; на объёмах маленьких складов это
  незаметно, индексы начинаются с `org_id`.
- Отладка «почему не видно» — сначала проверить, поставлен ли `app.org_id`.
