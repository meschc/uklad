# API дорожной карты

Договор между страницей `/roadmap` и сервером Уклада. Клиент — `src/site/lib/roadmap/port.ts`
(`httpPort`); пока сервера нет, работает `localPort` (всё в браузере). Сервер включается
переменной сборки `VITE_ROADMAP_API=https://…/roadmap`. Правится вместе с `port.ts`.

## Сценарий

1. Посетитель жмёт стрелку голоса или «Предложить идею».
2. Без входа открывается окно: почта и согласие на обработку данных → `POST /auth/code`.
3. Код из письма → `POST /auth/verify` → токен. Голос или идея, ради которых входили,
   выполняются сразу после входа.
4. Голос засчитывается по нажатию (интерфейс меняет счётчик до ответа и откатывает при
   отказе), повторное нажатие снимает его.
5. Идея уходит на разбор (`review`) и видна только автору, пока её не примут.

## Запросы

Все тела — JSON. Авторизация — `Authorization: Bearer <token>`.

| Метод и путь             | Тело                                | Ответ                             |
| ------------------------ | ----------------------------------- | --------------------------------- |
| `POST /auth/code`        | `{ email, consent: { data, ads } }` | `204`. Без `consent.data` — `400` |
| `POST /auth/verify`      | `{ email, code }`                   | `{ token, user: { email } }`      |
| `GET /board`             | — (токен необязателен)              | `{ counts, mine, ideas }`         |
| `PUT /votes/:itemId`     | `{ value: 1 \| -1 }`                | `{ count }` — итог пункта после   |
| `DELETE /votes/:itemId`  | —                                   | `{ count }` — свой голос снят     |
| `GET /comments/:itemId`  | — (токен необязателен)              | `RoadmapComment[]`                |
| `POST /comments/:itemId` | `{ text }` (до 1000 знаков)         | `RoadmapComment`                  |
| `POST /ideas`            | `{ title, details, track }`         | `SubmittedIdea`                   |

- `counts` — `{ [itemId]: number }`, итог «за» минус «против»; `mine` — `{ [itemId]: 1 | -1 }`, голоса вошедшего;
  `ideas` — его идеи: `{ id, title, details, track, status: "review"|"accepted"|"declined", createdAt }`.
- `RoadmapComment` — `{ id, author, text, createdAt }`; `author` — начало почты без домена. Писать комментарии может только вошедший; серверу нужны лимит частоты и жалоба на комментарий до открытия записи для всех.
- `itemId` — id из `src/site/data/roadmapItems.ts`; позже — узел карты продукта (`mapNode`).

## Коды ошибок

| Код   | Значение для интерфейса             |
| ----- | ----------------------------------- |
| `401` | токен недействителен — войти заново |
| `410` | код устарел                         |
| `422` | код неверный                        |
| `429` | слишком часто                       |

## Что обязан сервер

Требования треда «Безопасность продукта» (21.10.2026).

1. **Токен** случайный и непредсказуемый (не меньше 128 бит), на сервере хранится хешем.
   Формат `local:<почта>` — только локальная заглушка, сервер его никогда не принимает.
2. **Сессия** — лучше cookie `HttpOnly; Secure; SameSite=Lax`, а не Bearer в `localStorage`:
   токен из хранилища уносит любой XSS. Пока клиент шлёт Bearer — это принятый риск, его снимаем
   переходом на cookie вместе с запуском сервера.
3. **`devCode`** настоящий сервер не возвращает никогда; клиент на сетевом порте его не показывает
   (`port.live`).
4. **`POST /auth/code`** всегда отвечает `204`, есть такая почта или нет. Лимиты: не больше 1 кода в
   минуту и 5 в час на почту, отдельный лимит на IP — защита от рассылки писем на чужой ящик.
5. **Код**: 6 цифр, живёт 10 минут, хранится хешем, сравнение за постоянное время, после 5 неверных
   попыток сгорает. Письмо — с адреса домена.
6. **Против накрутки голосов**: голос — один на пункт и подтверждённую почту, лимит новых аккаунтов
   на IP, блок-лист одноразовых почтовых доменов. За готовые пункты (`status: done`) голос не
   принимать.
7. **Идеи**: заголовок до 90, текст до 1500 символов; при выводе только экранировать (никакого
   HTML или markdown в разметку); публиковать только после разбора.
8. **Согласие** на обработку данных хранить с датой и версией текста (152-ФЗ); рассылка — только
   при `consent.ads`.
9. **Выход** стирает из браузера почту и токен (`uklad.roadmap.session`) — клиент делает это уже
   сейчас.
10. Уведомлять голосовавших письмом при смене статуса пункта — в планах, на странице не обещаем.
