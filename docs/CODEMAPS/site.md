# Codemap · витрина (`src/site`)

Вторая точка входа проекта и почти половина его кода: маркетплейс складов,
лендинг, тарифы, контакты и правовой раздел. С кабинетом (`src/components`,
`src/lib`) витрина делит только токены темы, `cn` и примитивы `ui/` — всё
остальное у неё своё, включая маршрутизацию и словарь. Почему так — в
[ADR 0002](../adr/0002-mpa-two-entry-points.md) и
[ADR 0003](../adr/0003-own-i18n.md).

Главное отличие от кабинета: витрину читает робот. Отсюда всё её устройство —
настоящие пути вместо хэша, статические файлы вместо пустого `div id="root"`,
шапка документа чистой функцией, чтобы одинаково считаться и в браузере, и при
сборке. 76 адресов на каждом языке, 152 файла на выходе.

## Каркас

```
main.tsx         точка входа браузера: normalizeUrl() до первой отрисовки
                 (старые ссылки `#/market`, `?lang=en` приводятся к нынешнему
                 виду — иначе страница мигнёт чужим содержимым), затем
                 SiteErrorBoundary → SiteApp. Порядок стилей важен: сначала
                 `../index.css` (токены, Tailwind), потом `site.css`
SiteApp          витрина целиком: шапка, страница по маршруту, подвал, баннер
                 cookie. Здесь же общие для всех страниц хуки — типографика,
                 тема, плавная прокрутка, перехват ссылок — и запись шапки
                 документа в живой документ. Прокрутка сбрасывается по
                 `scrollKey`: у складов и документов сменой страницы считается
                 и переход между складами (`pushState` прокрутку не трогает)
LandingPage      порядок секций = порядок вопросов селлера; тёмные блоки стоят
                 через один. Комментарий в файле объясняет каждый шаг
SellersPage      отдельная страница «Селлеру»: путь от выбора склада до товара
                 у покупателя, что видно в кабинете, доска заявки, чат
SiteErrorBoundary  экран сбоя витрины. Классовый компонент, поэтому язык берёт
                 функцией `getLang`, а не хуком
entry-server.tsx входная точка сборки: та же витрина, но в строку. Выставляет
                 маршрут и язык ДО первой отрисовки (`SiteApp` читает их
                 через `useSyncExternalStore`), возвращает разметку, шапку,
                 Schema.org и путь файла. Про файловую систему не знает —
                 это дело `scripts/prerender.mjs`
site.css         правки поверх общей базы: страница вместо экрана на всю
                 высоту, акцент в крупном заголовке, ползунок цены, полоска
                 дожития вкладки, классы появления `.reveal` / `.is-in`
```

## components/ — общее для страниц

```
SiteHeader       шапка: на лендинге пункты — якоря его секций, на остальных
                 страницах — ссылки на соседние разделы. «Складам» стоит
                 раньше «Селлеру»: покупатель Уклада — склад
SiteFooter       подвал = карта сайта для робота: только отсюда есть ссылки на
                 семь правовых документов. Всё, что ведёт на страницу, —
                 настоящая ссылка. Здесь же оговорка о демо-реквизитах
                 (`ORG.filled`) и вызов баннера cookie обратно
CookieBar        согласие на cookie: две равнозначные кнопки, крестика нет
                 (закрытие без выбора — ни да, ни нет), появляется с задержкой.
                 Открыт он или нет — общее состояние (`useCookieBannerOpen`),
                 а не своё: низ экрана один, и полоса сравнения его уступает
ConsentChecks    две галочки под формой, и они обязаны быть двумя: согласие на
                 обработку данных — отдельное поле от рекламного, оба пустые,
                 отказ от рекламы ничего не блокирует (152-ФЗ)
NotFoundScreen   один тупик на три случая: неизвестный раздел, снятый склад,
                 устаревшая ссылка на документ. Разница только в тексте
Logo             знак «Уклада»: стеллаж и коробка на средней полке. Цвет
                 фирменный, `currentColor` намеренно не используется
BrandMark        знак площадки: логотип из `public/brands` на круге её цвета.
                 Форма задаётся здесь, потому что у чужих логотипов не
                 совпадает ничего — ни пропорции, ни скругления
SectionHead      шапка секции (надзаголовок · заголовок · подводка) — семь
                 повторений, разъехавшиеся кегли первым делом выдают «сайт по
                 кускам»
Reveal           появление блока при входе в кадр: один IntersectionObserver,
                 дальше CSS. Наблюдение снимается сразу — блок появляется один
                 раз; `as` сохраняет семантику обёртки
CountUp          число, досчитывающееся в кадре: rAF с замедлением, итог сразу
                 в `aria-label`, чтобы скринридер не поймал середину анимации
ChatPanel        чат с кладовщиком там, где возник вопрос (у позиции, у
                 поставки). Тема подставляется сама. Ответ склада НЕ
                 придумывается — панель показывает только факт отправки
PricingScreen    тарифы: страница обязательная, а не маркетинговая — оферта
                 ссылается на неё. Два кошелька (селлер — за функции, склад —
                 подпиской), порядок от бесплатного к платному
ContactsScreen   контакты + обязательное раскрытие (149-ФЗ, ЗоЗПП) из того же
                 `ORG`, что и правовые страницы; форма с ConsentChecks
```

## components/market/ — каталог складов

```
MarketScreen     каталог: условия слева, список или карта справа,
                 «Показать ещё» порциями; на узком экране фильтры уезжают в
                 шторку. Карта под `Suspense` — leaflet не грузится тем, кто
                 остался в списке
Filters          панель условий. Все переключатели работают на «и», и об этом
                 написано прямо под площадками: иначе пустой список читается
                 как поломка витрины
VolumeBar        объём селлера четырьмя числами — то, что превращает витрину в
                 сравнение: у каждой карточки появляется одна одинаково
                 посчитанная величина, месяц под этот оборот
WarehouseCard    карточка списка: прайс на одинаковых местах у всех складов —
                 ради этого витрина и затевалась. Переключатель сравнения
                 (`CompareToggle`, предел `COMPARE_LIMIT`) — сосед ссылки, а не
                 её потомок: кнопка внутри ссылки ломает и клик, и клавиатуру
CompareBar       полоса отмеченных внизу витрины: между первой отметкой и
                 последней проходит полторы страницы прокрутки, и набор должен
                 быть виден всё это время. Пока висит баннер cookie — полосы
                 нет вовсе, низ экрана у них общий
CompareSheet     сравнение таблицей: строка на показатель, колонка на склад,
                 лучшее помечено цветом и словом. Отсюда же уходит заявка сразу
                 во все отмеченные — с тем же согласием, что и одиночная
WarehouseCover   обложка: фотография либо плита в оттенке склада с буквой.
                 Слот одной высоты у всех — иначе список читается как
                 «часть картинок не загрузилась». Авторы снимков —
                 `public/photos/warehouses/CREDITS.md`
WarehouseAvatar  знак склада: тот же оттенок, что у обложки (`warehouseTint`),
                 первая буква названия
MarketMap        карта: метки divIcon'ами в цвет склада, чтобы точка и строка
                 списка узнавались друг в друге. География — половина выбора
                 фулфилмента
WarehouseScreen  страница склада: визитка, факты, прайс, условия, площадки,
                 доверие (форма регистрации, реестр), чат. `place()` не
                 печатает «Москва, Москва» — город и регион там совпадают
```

## data/ — данные витрины

```
warehouses.ts    генератор складов: детерминированный (`mulberry32` от
                 фиксированного зерна) — набор, перетасовывающийся на каждой
                 перезагрузке, читается как сломанный
warehousesRepository.ts  единственное место, знающее, откуда берутся склады
                 (п.3.2.5). СИНХРОННО, в отличие от `@/lib/data`: витрина
                 предрендерится, асинхронное чтение дало бы пустые страницы
                 роботу. Реестр приедет НА СБОРКЕ, а не при человеке
cities.ts        география: центры городов, вокруг них разбрасываются склады.
                 `weight` — сколько складов на город; рынок и правда стянут к
                 Москве, равномерная россыпь врала бы селлеру
marketplaces.ts  площадки фулфилмента; знаки из `public/brands` — те же, что у
                 экрана интеграций в кабинете
plans.ts         тарифы данными, а не строками в вёрстке: оферта ссылается на
                 цены, и разъехаться им нельзя (ст. 10 ЗоЗПП)
org.ts           реквизиты владельца — единственное место. ИП, а не ООО (нет
                 КПП, ОГРНИП вместо ОГРН, выписка из ЕГРИП). Значения
                 демонстрационные и невалидны намеренно, каждое нарушает по
                 два правила выдачи; пока `filled: false`, подвал говорит об
                 этом вслух
brand.ts         название марки: на английской версии латиницей. В данных, а
                 не в `components/Logo` — имя нужно заголовкам, разметке и
                 подвалу, и тянуть ради строки svg на полсотни строк незачем
legal/           семь документов текстом, а не разметкой: их правят юристы, из
                 текста бесплатно собираются оглавление и якоря. index.ts —
                 реестр в порядке чтения, types.ts — модель блоков.
                 Документы НЕ переводятся и не сокращаются
```

## lib/ — правила витрины

```
route.ts         маршрутизация на настоящих путях, без роутера: parsePath,
                 useRoute (useSyncExternalStore), href, routePath, navigate
                 через `history.pushState`, normalizeUrl для старых ссылок.
                 Адрес всегда с завершающей косой чертой, иначе `/market` и
                 `/market/` — две записи в индексе
routes.ts        полный список адресов: по нему предрендер собирает файлы, из
                 него же строится `sitemap.xml` с `xhtml:link` на языковые
                 версии. Карта сайта отдельным файлом в `public` жила своей
                 жизнью и о новых складах узнавала последней
lang.ts          язык — сегмент пути (`/en/`), а не параметр: у английской
                 версии должен быть свой адрес, иначе её нет в выдаче.
                 Приоритет источников: путь → `?lang=` → память → браузер → ru
basePath.ts      корень, из которого отдаётся витрина (`/` или подкаталог).
                 Адреса собираются и разбираются только этими двумя функциями
copy.ts          `c("Русский", "English")` рядом с компонентом + `useT()`;
                 `t.plural` зовёт `plural.ts` только на русском
plural.ts        три русские формы; своя, чтобы не тянуть словарь кабинета
typography.ts    неразрывные пробелы после коротких слов — на всю витрину,
                 включая тексты, которых ещё нет. Список предлогов закрытый:
                 правило «всё до трёх букв» утащило бы «шт», «мм», «WB»
eyebrow.ts       надзаголовок секции одной строкой классов. Общего кода с
                 `@/components/ui/eyebrow` нет намеренно: две сборки, и
                 разрядка с цветом у витрины свои
pageMeta.ts      заголовок, описание и канонические адреса — чистой функцией.
                 Отдельно от SiteApp потому, что то же самое нужно предрендеру,
                 который React не запускает: два источника заголовков
                 разошлись бы
meta.ts          запись посчитанного в документ: title, description, canonical,
                 hreflang, noindex, lang. В браузере правит живой документ, при
                 сборке — разметку до робота
jsonLd.ts        Schema.org: хлебные крошки и владелец сайта. Складов здесь
                 намеренно НЕТ — размечать выдуманную компанию значит соврать
                 в машиночитаемом виде
filters.ts       отбор складов + границы ползунка цены из самих данных.
                 Единственное место, читающее `WAREHOUSES` мимо репозитория:
                 обратная ссылка замкнула бы модули в кольцо
estimate.ts      месяц на этом складе под объём селлера. Нарочно простое
                 умножение по прайсу, без коэффициентов, которых мы не знаем:
                 врать точностью хуже, чем не считать
compare.ts       сравнение отмеченных складов: toggleCompare, compareRows,
                 bestIndexes, `COMPARE_LIMIT = 4`. Только числа с понятным
                 направлением — «Wildberries лучше, чем Ozon» неверно
warehouseTint.ts пара цветов склада по тону: фон плитки и буква. Отдельным
                 файлом, потому что знак и обложка одного склада обязаны быть
                 одного цвета
theme.ts         тема по настройке устройства, переключателя на витрине нет.
                 Первую установку класса делает скрипт в `index.html`, здесь —
                 только подписка на смену на ходу
cookieConsent.ts выбор в баннере (localStorage, не сами cookie) и событие,
                 которым подвал просит баннер показаться снова. Здесь же
                 признак «баннер сейчас открыт» (`useCookieBannerOpen`) —
                 модулем, а не состоянием внутри `CookieBar`: он нужен соседям
                 по низу экрана
useLinkNavigation.ts  переходы без перезагрузки при настоящих `<a href>`:
                 один перехват на документ, а не обработчик на каждую ссылку.
                 Непонятое отдаётся браузеру — перезагрузка это запасной путь
useSmoothScroll.ts    плавная прокрутка на Lenis (свой цикл дважды ломался на
                 попытке отличить мышь от тачпада). Вложенная прокрутка
                 разрешена, карта Leaflet исключена, `anchors` выключены
useScrollProgress.ts  насколько блок пройден: считается от центра экрана,
                 пересчёт в `requestAnimationFrame`
useOverlay.ts    общее для слоёв: Esc закрывает, фон не прокручивается. Колбэк
                 в ref, иначе эффект перезапустится и запомнит подменённый
                 `overflow` — страница осталась бы заблокированной
```

## Предрендер

```
npm run build → tsc -b → vite build → build:ssr → node scripts/prerender.mjs
                                                  Предрендер: 152 страниц,
                                                  карта сайта на 76 адресов
```

`scripts/prerender.mjs` берёт собранный `dist/index.html` как шаблон, зовёт
`render(route, lang)` из `dist-ssr/entry-server.js` на каждую пару из
`SITE_ROUTES × LANGS`, подставляет шапку и Schema.org и кладёт файл по адресу
(`/en/legal/offer/` → `dist/en/legal/offer/index.html`). Там же пишется
`sitemap.xml`. Разметка не гидрируется, а перерисовывается заново: у витрины
есть состояния, которых при сборке не существует — тема устройства, язык из
памяти браузера, согласие на cookie.

## Соглашения витрины

- Тексты — только парами `c(ru, en)`; забыть перевод не даёт тип.
- Внутренняя ссылка — настоящий `<a href>` с завершающей косой чертой. Кнопка
  с обработчиком роботу не видна, а человеку не даёт Cmd-клик и «копировать
  адрес».
- Всё, что нужно шапке документа, считается чистой функцией: у браузера и
  предрендера один и тот же источник.
- Данные о складах берутся из `warehousesRepository`, а не из `WAREHOUSES`.
  Исключение одно и объяснено — `lib/filters.ts`.
- Правовые документы не переводятся и не сокращаются.
- Новый адрес добавляется в `lib/routes.ts` — иначе страница не попадёт ни в
  сборку, ни в карту сайта.
