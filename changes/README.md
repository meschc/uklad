# Записи истории изменений

Сюда PR с заметной снаружи правкой кладёт **один новый файл** — свою запись
для истории изменений. `package.json` и `CHANGELOG.md` в PR не трогают: версия
считается сама — база из `package.json` плюс число записей в этой папке, тег
`vX.Y.Z` и релиз на GitHub ставит `.github/workflows/release-tag.yml` после
вливания. Двум PR нечего делить: разные файлы не конфликтуют.

Имя — любое уникальное, лучше дата и тема: `2026-11-21-bank-po-bik.md`.
Записи не удаляют и не переименовывают — на них стоит счёт версии.

Форма — как раздел Keep a Changelog, без заголовка версии:

```markdown
### Добавлено

- **Банк подставляется по БИК**: в реквизитах партнёра достаточно ввести БИК —
  название банка и корр. счёт заполнятся сами.
```

Разделы: `Добавлено`, `Изменено`, `Исправлено`, `Убрано`, `Безопасность`.
Перекладки кода, формат и зависимости — без записи. Проверка формы —
`node scripts/release.mjs check origin/main`, её же гоняет CI.
