# Уклад

WMS для маленького фулфилмент-склада плюс витрина, на которой селлер такой склад
находит. В репозитории это две части одной сборки: сайт по адресу `/` —
лендинг, каталог складов, тарифы и правовые документы; демо WMS по адресу
`/app/` — то, чем пользуется сам склад.

Демо: план склада рисуется мышью, товар раскладывается по конкретным
ячейкам, а дальше по этому плану работает вся смена — приёмка, задания, сборка,
отгрузка, печать ярлыков.

Ставка на то, чего обычно нет у складского софта этого размера: склад видно.
Не таблица адресов «A-01-03-02», а мезонин сверху, где занятая ячейка отличается
от пустой цветом, и место для новой поставки подбирается по реальным габаритам
коробки, а не «на глаз».

Работает целиком в браузере: бэкенда нет, данные лежат в `localStorage`.

## Запуск

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5174` (порт закреплён) — на сайте; демо
рядом, на `http://localhost:5174/app/`. При первом запуске подсевается
демо-склад: каталог товаров, персонал, поставки, заявки и рейсы за последние
70 дней — чтобы экраны были живыми, а не пустыми формами.

## Что внутри

**Витрина складов.** Каталог фулфилмент-операторов с фильтрами по городу,
площадкам, услугам и температурному режиму, картой и карточкой склада, из
которой уходит заявка. Склады и цены сгенерированы для демонстрации — об этом
сказано на самой витрине, а не мелким шрифтом внизу.

**Тарифы.** Витрина зарабатывает на двух разных кошельках, и это разделение —
не оформление, а условие честной выдачи. Селлер не платит за то, ради чего
пришёл: каталог, фильтры, карта, карточки и заявки бесплатны, комиссии с заявки
и платы за отклик нет — иначе наверху списка оказался бы не лучший склад, а тот,
кто больше занёс. Селлер платит поштучно за «взгляд внутрь» — план склада,
свои остатки по ячейкам, расчёт хранения под свой габарит, сравнение таблицей,
проверка оператора по реестрам. Склад платит подпиской за учётную систему.
Цены живут данными в [`src/site/data/plans.ts`](src/site/data/plans.ts), а не
строками в вёрстке: страница «Тарифы» объявлена неотъемлемой частью оферты, и
две разные цифры в двух местах были бы не опечаткой, а расхождением с договором.

**Правовой контур.** Семь документов, которые обязан раскрывать сайт-агрегатор
по российскому праву: реквизиты владельца, пользовательское соглашение, оферта,
политика обработки персональных данных, согласие, политика cookie и правила
рекомендательных технологий. Плюс баннер cookie, который ничего не записывает
до выбора, и раздельные галочки согласий под формами.

**Редактор плана.** Секции стеллажей расставляются на плане этажа, у каждой —
реальные габариты, ярусы и число ячеек. Отсюда берутся размеры ячейки, по
которым потом проверяется, влезет ли товар.

**Раскладка товара.** Подбор места считает габариты коробки и приоритет ячеек:
ходовое ближе к проходу, запас выше. Ячейку можно закрыть от автоподбора, не
убирая с неё товар.

**Фулфилмент-контур.** Ожидаемая поставка → приёмка (с расхождениями план/факт)
→ размещение → заявка на отгрузку → сборка → рейс. Плюс две схемы поверх:
бронирование под ещё не приехавшую поставку (дропшиппинг) и кроссдокинг, когда
товар уходит на сборку прямо с приёмки, минуя полку.

**Печать.** Ярлыки ячеек, полок и коробок со штрихкодом Code128, конструктор
шаблонов, печать плана этажа.

**Интеграции.** Площадка под обмен с маркетплейсами, учётными системами и
доставкой: по каждой системе известно, какой это API, какая авторизация и какие
поля нужны. Самого обмена в демо нет — ключи вводятся заранее и остаются в
браузере.

## Стек

React 18 + TypeScript, Vite (две точки входа), Zustand (срезы + `persist`),
Tailwind и shadcn/ui, Vitest и Playwright. Leaflet — карта на витрине. Три.js —
под флагом, для 3D-вида плана.

## Структура

```
index.html         вход сайта; app/index.html — вход демо WMS
src/site/          лендинг, витрина складов, тарифы, правовые документы
src/components/    экраны и UI демо; fulfillment/ — приёмка, сборка, отгрузка
src/lib/           доменная логика: placement, address, barcode, i18n
src/lib/store/     стор по срезам (17 штук), история правок, посев демо-данных
src/lib/data/      репозитории поверх localStorage — экраны туда не ходят сами
e2e/               сквозные тесты Playwright
docs/CODEMAPS/     карты кода: компоненты, стор, домен
docs/design/       дизайн-система и разбор знака: BRAND.md
public/brands/     логотипы вендоров для списка интеграций
```

Подробности по правилам работы со стором и историей — в [CLAUDE.md](CLAUDE.md) и
`docs/CODEMAPS/`.

## Тесты

```bash
npm test
```

Тестируется не React, а расчёты, которые ошибаются молча: занятость ячеек,
подбор места, бронь под поставку, кроссдокинг, сборка заявки. Неверный ответ в
этих местах выглядит как обычный, и заметить его можно только по расхождению
через неделю.

```bash
npm run test:e2e
```

Сквозные — Playwright, два прогона на один набор: широкий экран и Pixel 7.
Проверяются пути, которыми ходит человек: лендинг → витрина → карточка склада →
заявка, семь правовых документов по прямым ссылкам, выбор cookie и согласия под
формами, отсутствие горизонтальной прокрутки на каждой странице. Демо
`/app/` проверяется отдельно — коротким маршрутом «список складов → склад →
раздел».

Прогон идёт по **собранному** сайту на порту 4174, а не по дев-серверу. Причин
две. Ломается обычно сборка: сайт и демо собираются двумя входами
(`build.rollupOptions.input`), и «`/app/` открывается» — утверждение о
результате `vite build`, а дев-сервер про MPA ничего не знает. И порт: на 5174
живёт дев-сервер с настоящим планом склада в `localStorage`, а тесты чистят
хранилище своего origin — совпадение портов означало бы, что прогон тестов
стирает рабочие данные.

Первый запуск требует браузера: `npx playwright install chromium`.

## Оговорки

Это демоверсия, а не продакшен: бэкенда нет, пользователей и прав нет, данные
живут в браузере и чистятся вместе с ним. Интеграции — подготовленная площадка без
реального обмена. Формы на сайте ничего не отправляют и говорят об этом прямо
в ответе.

Склады, цены и рейтинги на витрине сгенерированы. Реквизиты владельца в
[src/site/data/org.ts](src/site/data/org.ts) — демонстрационные, и подобраны так,
чтобы не могли принадлежать никому: у ИНН и ОГРН неверные контрольные разряды и
несуществующий код региона `00`, у индекса — недопустимая первая цифра, у
телефона — невыделенный код `200`. Случайные числа для этого не годятся, они как
раз попадают в чей-нибудь настоящий ИНН; разбор арифметики — в шапке файла. Пока
`ORG.filled` равен `false`, правовые страницы печатают короткую пометку об этом;
после подстановки настоящих реквизитов достаточно поднять флаг, и пометка
исчезнет везде разом. Домен `uklad.example` в `public/robots.txt` и
`public/sitemap.xml` — зона, зарезервированная RFC 2606: зарегистрировать её
нельзя, поэтому её и меняют на настоящую при выкладке.

Всё, что нужно подставить перед публикацией, собрано одним списком в
[docs/LAUNCH.md](docs/LAUNCH.md) — с путями к файлам и с тем, откуда брать
значения.

Логотипы в списке интеграций принадлежат их правообладателям и используются
только чтобы обозначить, с какой системой идёт обмен.
