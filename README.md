# Уклад

Прототип WMS для маленького фулфилмент-склада: план склада рисуется мышью, товар
раскладывается по конкретным ячейкам, а дальше по этому плану работает вся смена
— приёмка, задания, сборка, отгрузка, печать ярлыков.

Ставка на то, чего обычно нет у складского софта этого размера: склад видно.
Не таблица адресов «A-01-03-02», а мезонин сверху, где занятая ячейка отличается
от пустой цветом, и место для новой поставки подбирается по реальным габаритам
коробки, а не «на глаз».

Работает целиком в браузере: бэкенда нет, данные лежат в `localStorage`.

## Запуск

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5174` (порт закреплён). При первом запуске
подсевается демо-склад: каталог товаров, персонал, поставки, заявки и рейсы за
последние 70 дней — чтобы экраны были живыми, а не пустыми формами.

| Команда | Что делает |

## Что внутри

**Редактор плана.** Секции стеллажей расставляются на плане этажа, у каждой —
реальные габариты, ярусы и число ячеек. Отсюда берутся размеры ячейки, по
которым потом проверяется, влезет ли товар.

**Раскладка товара.** Подбор места считает габариты коробки и приоритет ячеек:
ходовое ближе к проходу, запас выше. Ячейку можно закрыть от автоподбора, не
убирая с неё товар.

**Фулфилмент-контур.** Ожидаемая поставка → приёмка (с расхождениями план/факт)
→ размещение → заявка на отгрузку → сборка → рейс. Плюс две схемы поверх:
бронирование под ещё не приехавшую поставку (дропшиппинг) и кроссдокинг, когда
товар уходит на сборку прямо с приёмки, минуя полку.

**Печать.** Ярлыки ячеек, полок и коробок со штрихкодом Code128, конструктор
шаблонов, печать плана этажа.

**Интеграции.** Площадка под обмен с маркетплейсами, учётными системами и
доставкой: по каждой системе известно, какой это API, какая авторизация и какие
поля нужны. Самого обмена в прототипе нет — ключи вводятся заранее и остаются в
браузере.

## Стек

React 18 + TypeScript, Vite, Zustand (срезы + `persist`), Tailwind и shadcn/ui,
Vitest. Три.js — под флагом, для 3D-вида плана.

## Витрина

Публичная страница продукта живёт отдельным проектом в `site/`: дашборд
статусов работ, роадмап колонками и по кварталам, журнал обновлений.

```bash
cd site && npm install && npm run dev   # http://localhost:5175
```

Сборка своя, зависимости свои, палитра общая — `site/src/tokens.css`
генерируется из `src/index.css` командой `npm run tokens`. Содержимое роадмапа
правится в `site/src/data/roadmap.ts`; подробности — в [site/README.md](site/README.md).

## Структура

```
src/components/    экраны и UI; fulfillment/ — приёмка, сборка, отгрузка
src/lib/           доменная логика: placement, address, barcode, i18n
src/lib/store/     стор по срезам (17 штук), история правок, посев демо-данных
src/lib/data/      репозитории поверх localStorage — экраны туда не ходят сами
docs/CODEMAPS/     карты кода: компоненты, стор, домен
public/brands/     логотипы вендоров для списка интеграций
site/              витрина: роадмап и статусы работ (своя сборка)
```

Подробности по правилам работы со стором и историей — в [CLAUDE.md](CLAUDE.md) и
`docs/CODEMAPS/`.

## Тесты

```bash
npm test
```

Тестируется не React, а расчёты, которые ошибаются молча: занятость ячеек,
подбор места, бронь под поставку, кроссдокинг, сборка заявки. Неверный ответ в
этих местах выглядит как обычный, и заметить его можно только по расхождению
через неделю.

## Оговорки

Это прототип, а не продукт: бэкенда нет, пользователей и прав нет, данные живут
в браузере и чистятся вместе с ним. Интеграции — подготовленная площадка без
реального обмена.

Логотипы в списке интеграций принадлежат их правообладателям и используются
только чтобы обозначить, с какой системой идёт обмен.
